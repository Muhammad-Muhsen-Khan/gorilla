What follows

The corpus is the likely cause

Every behaviour above is consistent with a training set of single-exchange examples: a user asks, the model emits calls, the example ends. Nothing in it teaches the model to read a <tool_response> that contains an error and try again, so at inference it does the one thing it did learn — produce a fluent reply and stop.

Worth checking directly: how many conversations in toolace-tooling-sft contain more than one assistant turn, and how many contain a tool response carrying an error the next assistant turn has to act on. If the second number is near zero, that is the finding, and it is a data problem rather than a hyperparameter one.

The decisive control is the untrained base model. If qwen3-4b-base-FC also scores ~2% on multi-turn, this is Qwen3-4B-Base's own ceiling and the SFT simply never addressed it. If the base scores meaningfully higher, the fine-tune removed an ability — a much more serious result, and one that would reframe the 83% single-turn number as narrow rather than strong.
