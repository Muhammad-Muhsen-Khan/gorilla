Twenty-Two Checkpoints

We fine-tuned Qwen3-4B-Base on tool-calling data in two variants — one with reasoning traces, one without — and saved a checkpoint every epoch for ten epochs. This is all twenty of them on BFCL v4, plus the untrained base model and the official instruct model as bookends.

The single-turn result is strong and arrives after one epoch. The multi-turn result is close to zero and stays there. And the most dramatic number of all — the base model's 0.00, implying it cannot call functions — turns out to be a parser artifact: re-scoring the same generations leniently puts it at 58.67%. That reframes what the fine-tune bought, and it is the finding worth carrying.

Part one

What BFCL v4 actually measures

The Berkeley Function Calling Leaderboard tests whether a model can pick the right function and fill its arguments correctly. Version 4 keeps the single-turn and multi-turn categories from v1–v3 and adds agentic ones on top, so running v4 gives the earlier signal too. We ran 20 of its 22 scored categories, 5,017 generated entries per model.

Category groupEntriesWhat it asks of the modelHow it is scored
Non-live simple / multiple / parallel1,150Pick one function, or several, or several at once, from a hand-written catalogueAST match
Live (user-contributed)2,251Same, but on real function schemas donated by users — messier, more realisticAST match
Irrelevance / relevance1,140Recognise when no offered function fits, and abstain — or when one doesAbstention correctness
Multi-turn (4 categories)800Hold a conversation against a live stateful API — a filesystem, a vehicle, a trading bot — across several user turns, including turns with a missing function or parameterFinal API state + response
Memory (kv / vector / rec-sum)465Read and write to a memory backend across a session and use what it storedFinal state
Web search (excluded)200Multi-hop search and page-reading via a live search APIAnswer match

The three scoring mechanisms differ in kind. AST match parses the emitted call and compares function name and arguments against accepted answers — it never executes anything. Multi-turn and memory are state-based: the benchmark runs the calls against a real Python object and compares the final state of that object to ground truth, so a conversation that reaches the right end state passes even by a different route, and one that gets every call right but leaves the state wrong fails.

The weighting is where the headline number comes from

BFCL v4's Overall Acc is not an average of categories. It is a fixed weighting that puts 70% of the score on multi-turn and agentic work:

10101030 · multi-turn40 · agentic
  • Non-live
  • Live
  • Irrelevance
Overall = 0.10·NonLive + 0.10·Live + 0.10·Irrelevance + 0.30·MultiTurn + 0.40·Agentic Agentic = mean(Memory, WebSearch)

We verified this against the published CSV: it reproduces every one of our 22 rows to the second decimal.

This means our Overall Acc figures are not comparable to the public leaderboard. We skipped web_search — the SerpAPI key on hand is free-tier, 250 searches against a category of multi-hop tasks needing several searches each, across 22 models. A missing category is scored as 0, not dropped, so web search being absent halves the agentic term and costs every model up to 20 points of Overall.

Comparisons within this table remain exact — all 22 models are missing the same category. Only the absolute Overall numbers are depressed.

Part two

What we ran

Two SFT runs over Qwen3-4B-Base on a ToolACE-derived corpus: one rendering assistant turns as bare tool calls (no-reason, 64 steps/epoch), one interleaving reasoning traces (reasoning, 86 steps/epoch). Ten epoch checkpoints each. All served through vLLM 0.8.5 in prompting mode with Qwen3's own tool template, which we verified renders byte-identically to the template the models were trained under.

Every model saw all 5,017 entries — no partial evaluation anywhere. The full suite took about five hours across eight A100s, most of it spent on the two reference models, which never emit a stop token and so run to the 2,048-token cap on every single generation.
